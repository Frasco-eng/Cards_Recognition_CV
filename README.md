A classical computer-vision pipeline that recognises **Briscola** (Italian deck) playing cards lying on a plain coloured towel, in real time from a webcam, from a recorded video, or from static test images. It handles single cards, **overlapped / partially covered cards**, and rejects other objects in the scene (hands, glasses, …). No neural networks are used: the pipeline is built from segmentation, blob analysis, SIFT features, matching and RANSAC.

Card games are often played by elderly people with poor eyesight. The idea is a system that reads the cards on the table for them.

A full description of the project, design choices and results is in [`Playing_Cards_Recognition_Report.pdf`](Playing_Cards_Recognition_Report.pdf). A demo of the result is in [`proj_video.mp4`](proj_video.mp4).

## Pipeline

1. **Deck creation (offline).** Each reference card photo in `images/` is segmented from the background, cropped, and saved in `deck/`. SIFT keypoints and descriptors are then computed for every card and stored as `Card` objects.
2. **Background capture.** At start-up the camera takes a photo of the empty towel. Its mean colour `μ` and inverse covariance `Σ⁻¹` are computed from that photo.
3. **Segmentation.** Each frame is segmented with the per-pixel **Mahalanobis distance** from the background colour distribution, followed by a threshold and morphological operations.
4. **Blob detection.** Connected components are extracted and filtered by size, so each blob is a candidate card or group of overlapped cards.
5. **Blob analysis.** For every blob:
   - extract SIFT keypoints and descriptors;
   - match blob → card with kNN (k=2) and **Lowe's ratio test**;
   - **cross-check** each match in reverse (card → blob), keeping only bidirectional matches;
   - fit a **RANSAC homography** and count the inliers (one vote per deck card).
6. **Decision.** A card is accepted for a blob when both of these hold:
   - **relative confidence**: inliers / best card's inliers ≥ `confidence`;
   - **absolute threshold**: inliers > `abs_thresh1`.

   Several cards can be accepted for the same blob, which is how overlapped cards are recognised.
7. **Repetitive-pattern heuristic.** On Cups and Coins, the Lowe ratio and RANSAC throw away many matches because the same figure repeats all over the card. When the main pipeline finds nothing, the suit (*seed*) is guessed from the one-way match votes. The card is then segmented internally and its figures are counted to get the number.
8. **Display.** Recognised card names and the FPS are drawn on the frame. A *hold* mechanism keeps the labels until the number of blobs changes.

## Usage

All scripts read a reference background photo for deck creation from `backgrounds/Background_deck.jpeg`. They also write the captured background to `backgrounds/Background_captured.png`. Create the `backgrounds/` folder and put a photo of your empty towel in it before running anything.

### Real time (`main_real_time.py`)

1. Set up a uniform, preferably green, towel with the camera looking down at the table from at most about 50 cm.
2. Choose the capture device in section 6/7 (`cv2.VideoCapture(0, cv2.CAP_DSHOW)`). `CAP_DSHOW` is Windows-only; on Linux/macOS use `cv2.VideoCapture(0)`.
3. Run `python main_real_time.py`.
4. For the first ~2 s, keep **only the empty towel** inside the red square while the background is captured.
5. Put cards on the table. Press `q` to quit.
6. If the results are poor, tune the parameters in section 4.

### Recorded video (`main_stream_video.py`)

1. Set `video_path` (default `test_videos/TestVideo4.mp4`) and `output_video` (default `video_results/out.mp4`) in section 4. Create these folders if they don't exist.
2. Run `python main_stream_video.py`. The first frames of the video are used as the background.

### Benchmark (`main_images_benchmark.py`)

1. Run `python main_images_benchmark.py`. It processes `test_images/CardTest1..14.jpeg` against the ground truth in `Test_True_Cards`.
2. It prints found / correct / missed cards, average time, FPS and confidences. It also appends the run to `results.xlsx` (sheets `Results` and `Parameters`).
3. This script uses only the main heuristic. The repetitive-pattern heuristic is not applied here.

### Notebook (`main_notebook.ipynb`)

Run the cells top to bottom. The notebook has the same structure as `main_real_time.py`, with explanations and `# ===== 7.x =====` markers in the main loop.

## Parameter tuning guide

The parameters depend on each other and on the setup (lighting, camera distance, towel), so retune them together when anything changes.

| Parameter | Typical range | Notes |
|---|---|---|
| `segment_threshold` | 20–60 | Lower it for brighter backgrounds. |
| `max_key_deck` | 1000–2000 | Keypoints per reference card. |
| `max_key_target` | 2000–5000 | Keypoints per blob. Use more the farther away the camera is. |
| `lowe_ratio1`, `lowe_ratio2` | 0.6–0.9 | Lower values are stricter. |
| `confidence` | 0.2–0.5 | The scripts use 0.3. |
| `abs_thresh1` | 5–15 | Minimum RANSAC inliers. 8 is recommended. |
| `abs_thresh2` | 10–20 | Minimum one-way matches for the seed vote. |
| `min/max_width`, `min/max_height` | setup dependent | Blob size band-pass filter. Retune it when the camera height changes. |
| `matcher` | `'bf'` / `'flann'` | Brute force (`'bf'`) is the default. |

## Limitations

- Needs a controlled environment: even lighting, no reflections on the cards, and a plain uniform background.
- The camera must see only the background while it is being captured.
- The repetitive-pattern heuristic covers only Cups and Coins, and only when the card **is not overlapped**.
- Performance changes with ambient light (time of day, flicker), so parameters may need retuning.

## Future work

- Adaptive threshold selection and noise filtering, for robustness to the environment.
- Overlap and occlusion handling in the repetitive-pattern heuristic.
- Support for other decks: pick a deck folder and build its `Card` array automatically.
